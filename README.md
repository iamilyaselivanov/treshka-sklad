# ТРЁШКА склад

Android-приложение складского учёта с offline-first синхронизацией.

## Гарантии сохранности

- Android сначала сохраняет полный снимок в SQLite.
- При подключённом сервере снимок и запись durable outbox создаются одной
  SQLite-транзакцией.
- Каждая серверная отправка имеет неизменяемый `mutationId`; повтор не создаёт
  повторную выдачу или вторую ревизию.
- PostgreSQL применяет снимок и idempotency-запись одной транзакцией.
- При несовпадении ревизий сервер сохраняет локальный снимок в
  `conflict_snapshots`, отвечает `409`, а Android не удаляет outbox.
- Pull выполняется только при пустом outbox, поэтому локальные изменения не
  затираются сервером.
- Миграции Android и PostgreSQL только добавляют таблицы/поля и не используют
  `DROP TABLE`.
- Основной локальный снимок имеет резервную предыдущую версию.

## Каталоги

- `android/` — Android WebView-приложение, SQLite, sync outbox и FCM.
- `public/prototype.html` — интерфейс и бизнес-логика.
- `server/` — FastAPI, PostgreSQL, локальное/S3-хранилище и отправка FCM.
- `tests/` — регрессионные браузерные тесты.

## Развёртывание на Timeweb Cloud

1. Создайте Ubuntu 24.04 LTS, публичный IPv4 и DNS-запись.
2. Установите Docker Engine и Compose.
3. Скопируйте `server/.env.example` в `server/.env`, задайте длинные случайные
   `POSTGRES_PASSWORD`, `JWT_SECRET`, начальный пароль администратора и домен.
4. Укажите домен в `DOMAIN`; Caddy автоматически выпустит TLS-сертификат.
5. Запустите:

   ```bash
   cd server
   docker compose up -d --build
   ```

6. Проверьте `https://ваш-домен/health`.
7. В Android: `Ещё → Сервер и синхронизация`, введите URL, логин и пароль.

Первое подключение существующей локальной базы автоматически ставит её в
outbox. Пустой сервер примет её как ревизию 1. Непустой сервер вернёт конфликт и
сохранит обе версии.

Существующие локальные аккаунты также импортируются. Их прежний SHA-256+salt
принимается только для первого серверного входа; сразу после успешной проверки
сервер заменяет его на Argon2id и удаляет legacy-хэш.

## Push

Создайте Android-приложение `com.treshka.sklad` в Firebase:

1. положите `google-services.json` в `android/app/` (файл исключён из Git);
2. сервисный ключ Firebase положите в
   `server/secrets/firebase-service-account.json`;
3. установите в `.env`:
   `FCM_CREDENTIALS=/run/secrets/firebase-service-account.json`;
4. пересоберите APK и сервер.

Без Firebase-конфигурации приложение продолжает работать и хранит адресные
уведомления внутри своей базы, но межустройственные системные push не отправляет.

## Фотографии и последующий переход в S3

Сейчас сервер может хранить сжатые JPEG в volume `media_data`. Переключение:

1. один раз выполните `python scripts/extract_inline_photos.py` для старых
   Base64-фотографий (оригинал в снимке при этом не удаляется);
2. создайте приватный бакет Timeweb S3;
3. заполните `S3_*` в `.env`;
4. запустите `python scripts/migrate_media_to_s3.py`;
5. после проверки установите `STORAGE_BACKEND=s3`.

Скрипт сначала загружает и проверяет объект, затем транзакционно меняет ссылку в
PostgreSQL. Старый локальный файл удаляется только после успешной фиксации.

## Резервные копии

`server/scripts/backup.sh` создаёт согласованный `pg_dump`, архив локальных
фотографий и SHA-256. На production его нужно запускать ежедневно по cron и
копировать результат за пределы самого VPS (позже — в S3). Восстановление
обязательно проверяется на отдельной тестовой базе перед обновлением сервера.

Ручной запуск: `docker compose exec api sh scripts/backup.sh`.
